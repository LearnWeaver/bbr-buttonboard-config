Setting up the keys

The game only sees a key that is bound to a button. A key with no binding sends nothing to the computer, so pressing it here does nothing. Bind two keys first:

  1. In the config app, open Configure and click the key you want for JUMP. Under Reports as, pick a number, for example 1.
  2. Click a second key for DUCK and pick a different number, for example 2. Two keys on the same number look like one key to the game.
  3. Come back here and press each key when asked.

A binding works as soon as you pick it. Press Save to board in the config app if you want it to stay after the board is unplugged. Keys already bound for your robot work too, as long as JUMP and DUCK are on different numbers.

In xinput mode only numbers 1 to 24 reach the game: 25 to 32 have no Xbox equivalent. In frc mode, and in config mode (CFG held at plug-in), any of 1 to 32 works. The config app can stay open in another tab while you play. If No controller seen yet stays up, press a bound key once: a browser only shows a gamepad after one of its buttons has been pressed.

Last run

A fast repeat is two presses of one key less than 60 ms apart. Nobody does that on purpose, so any at all means a switch is bouncing past its debounce or a lead is dropping out. Raise that tile's debounce in the config app, or check its cable.

How it works

The game reads the board the way the Driver Station does, as a gamepad, so it works in both USB modes. In frc mode, key numbers are the logical buttons the config app binds. In xinput mode they are Xbox names. A board in xinput mode shows up in Chrome or Edge on Windows. macOS has no driver for that kind of pad, so test xinput on the Driver Station laptop. Any key bound to a button or to a stick direction can be jump or duck.
